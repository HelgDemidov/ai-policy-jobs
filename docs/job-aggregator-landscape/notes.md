# Query-centric job aggregators — обновление знаний (2026-07-25)

Триггер: после направления 1 (см. `docs/ats-aggregator-sweep/notes.md`, 1 хит из ~24 организаций) куратор усомнился, что подход исчерпан одним проходом, и попросил обновить знания на примере методологии Luke Barousse (data-jobs YouTube/Kaggle автор) и аналогичных pet-проектов мониторинга вакансий. Гипотеза подтвердилась: **проблема была не в недостатке попыток, а в самой парадигме поиска.**

## Ключевой сдвиг: org-centric vs query-centric

Всё, что делалось в направлении 1 (и в первичном сборе шортлиста) — **org-centric**: сначала узнаём имя организации (вручную, через WebSearch по think tank'ам), потом ищем ЕЁ карьерную страницу/ATS. Это работает только если организация уже попала в наш список — и требует отдельного ATS-детектива на каждую.

Luke Barousse (проект «Data Analyst Job Postings», датасет на Kaggle/Hugging Face, `lukebarousse/data_jobs`) делает наоборот — **query-centric**: тянет результаты Google for Jobs по поисковому запросу (например, "data analyst"). Google Jobs сам агрегирует вакансии из тысяч источников — LinkedIn, Indeed, Glassdoor, ZipRecruiter, карьерные страницы компаний — в одну выдачу. Организация и её ATS обнаруживаются ПОПУТНО, как побочный продукт поиска по ключевому слову, а не как предварительное условие для поиска.

Практическое следствие для нас: запрос вроде **"AI policy analyst" / "emerging technology policy researcher" / "AI governance researcher"** через такой агрегатор нашёл бы вакансии у организаций независимо от того, на каком ATS они сидят — включая custom-сайты, которые направление 1 в принципе не может достать без отдельного HTML-скрейпера под каждый сайт.

### Выводы из живого тестирования

1. **Явные аутсайдеры для нашей ниши: RemoteOK и We Work Remotely.** Оба — 0 релевантных результатов, оба структурно tech/startup-центричны. Не стоит тратить время на интеграцию.
2. **Явный лидер среди бесплатных API без ключа: Himalayas.** Единственный из трёх дал реальные, релевантные хиты сразу, без тонкой настройки запроса.
3. **JobSpy — ценность сильно зависит от конкретного под-источника.** LinkedIn дал лучший результат из вообще всех протестированных источников, но это же самый хрупкий/рискованный (рейт-лимиты, серая зона ToS) — использовать экономно, не для частого автополлинга. Indeed — реальный, но смещённый в корпоративный сегмент. Google — не сработал вживую вообще (0/0), несмотря на теоретически широчайший охват (это и есть источник методологии Luke Barousse) — хрупкость скрейпинга не абстрактный риск, а наблюдаемый факт.
4. **Adzuna работает, но требует точной фразировки — и не любая фраза одинаково выигрывает от точного режима.** `what_phrase=think tank` — лучший единичный запрос вообще среди всех 5 источников по чистоте результата. Короткие/частые фразы (`AI policy`) не спасает даже `what_phrase`. Общие термины про «AI governance» — не проблема запроса, а честное отражение структуры рынка труда (там больше корпоративных compliance-позиций, чем think tank'ов). Мультистрановость (проверено gb+be) подтверждена рабочей — уникальное преимущество Adzuna относительно remote-only бордов.
5. **Три организации из шортлиста нашлись независимо через разные источники** — RAND Europe (LinkedIn), Centre for Long-Term Resilience (Adzuna), R Street Institute (Himalayas) — то есть query-centric подход реально пересекается с уже собранным org-centric шортлистом, а не существует отдельно от него. Плюс минимум 3 новые организации, ранее не встречавшиеся: InfluenceMap, European Macro Policy Network, Protect Democracy.

## Референсные DIY-пайплайны (архитектурные паттерны, не прямое заимствование кода)

Несколько похожих личных проектов непрерывного мониторинга вакансий, найденных при обновлении знаний — не для копирования, а как подтверждение, что наша собственная архитектура (SQLite + реконсиляция + cron-совместимость) — на верном пути:

- **job-search-pipeline** (github.com/dome317) — cron + скрейп нескольких платформ + SQLite + LLM-скоринг + доставка в Telegram. Структурно почти зеркалит то, что мы уже построили (коннекторы → SQLite → фильтрация), плюс следующий естественный шаг — уведомления и LLM-скоринг (см. пункт 3 нашего бэклога).
- **Zero-Cost Daily Job Alert Pipeline на GitHub Actions** (HackerNoon) — дедуп через JSON-файл, пайплайн идемпотентен (повторный прогон = no-op) — тот же принцип, что и наш `store.upsert_postings`.
- **swizjobsbot** (github.com/lucasnevespereira) — Telegram-бот + cron-паттерны для периодического опроса.

Общий вывод по этому классу проектов: связка «периодический скрейп → дедуп в лёгкой БД → уведомление» — устоявшийся, проверенный паттерн для персонального инструмента такого масштаба, и мы уже реализовали его ядро. Недостающая часть — ИСТОЧНИК данных (query-centric агрегатор вместо org-by-org ATS-охоты) и, опционально, канал уведомлений (Telegram/email вместо ручного открытия Streamlit-приложения).

## Рекомендация (обновлена по итогам живого тестирования)

Итоговый тулкит — **комбинация конкретных источников**, отобранных по фактическому результату теста, а не по типу инструмента в целом:

1. **Himalayas** — включить как основной источник Tier A. Бесплатно, без ключа, стабильно релевантен без специальной настройки запроса.
2. **Adzuna** — включить как основной источник Tier B, но **только с запросом `what_phrase=think tank`** (плюс, возможно, другими проверенными точными фразами конкретно под наш профиль — не «AI governance»/«AI policy», они не работают). Мультистрановость (`gb`, `be`, при необходимости другие коды) — реальный охват под гео-приоритет Tier B.
3. **JobSpy → LinkedIn-источник** — включить, но с осторожностью: лучший результат из всех протестированных источников (RAND Europe, явные think-tank-analyst позиции), однако требует экономного использования (не частый автополлинг) из-за рейт-лимитов и серой зоны ToS.
4. **JobSpy → Indeed-источник** — включить как второстепенный/более широкий источник; ожидать смещения в корпоративный AI-governance/compliance сегмент, не как основной сигнал.
5. **Не включать: RemoteOK, We Work Remotely, JobSpy → Google.** Все три дали ноль релевантных результатов вживую для нашей ниши, несмотря на теоретически широкий охват (особенно Google — ключевой источник методологии Luke Barousse, но эмпирически ненадёжный на практике).
6. Ранее запланированный «систематический проход по кураторским агрегаторам организаций» (Global Go To Think Tank Index, 80 000 Hours, EA Forum, EUjobs.co, On Think Tanks — статичные, вручную читаемые списки) остаётся **менее приоритетным**, чем интеграция источников выше — те дают то же самое (обнаружение новых организаций, подтверждено: InfluenceMap, European Macro Policy Network, Protect Democracy) плюс сами вакансии, живьём и непрерывно.

**Практический вывод для реализации коннектора:** независимо от источника, запрос должен быть настраиваемым per-source (не один и тот же keyword на все источники сразу) — то, что работает на Adzuna (`think tank`), не обязательно оптимально на Himalayas/LinkedIn, и наоборот. Схема конфига должна допускать разные search-term'ы на разные источники, а не единый глобальный запрос.
